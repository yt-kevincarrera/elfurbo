# El Furbo 2.0 · Plan de entrega

> **Para quien lo ejecute:** se hace de corrido, un PR detrás de otro. Cada PR
> sigue el mismo ciclo: implementar, pasar los tests, revisión con un subagente
> nuevo, arreglos, PR, merge (merge commit) y al siguiente.

**Spec:** `docs/superpowers/specs/2026-10-07-v2-comunidad-prestigio-torneos-design.md`.

## Reglas para todos los PRs

- **Ramas:** una por PR, desde `main` ya actualizado: `feature/v2-identidad`,
  `feature/v2-stats`, etc.
- **Commits:** a nombre de Kevin Carrera <kevin.cc@selector.dev>, sin ninguna
  atribución a IA.
- **Antes de abrir el PR:**
  - backend: `npm run typecheck` y `npm test`;
  - app: `dart format --output=none --set-exit-if-changed lib test`,
    `flutter analyze` y `flutter test`.
- **Migraciones nuevas** a partir de la `0008`. Cada columna nueva lleva un
  valor por defecto, para que la 1.x siga funcionando hasta la 2.0.0.
- **Comandos nuevos** en tres sitios a la vez:
  - el payload en `shared-fixtures/app-commands.json`;
  - el handler en `backend/src/sync/handlers.ts`;
  - el reductor en `lib/cloud/sync/reducers.dart`.
- **Reglas que se calculan en los dos lados:** casos en `shared-fixtures/*.json`
  que corren Dart y TypeScript.
- **Texto:** según `docs/tono.md`.
- **Producción no se toca** hasta el PR9. Staging se despliega solo con cada
  merge a `main`.
